# Request: Initial Evidence Map For AI-First Architecture

## Operationalized Intent

The project needs an evidence-backed map that can guide the first real architecture cycle without prematurely committing to a programming language, Ariadne rewrite, SimplyStore substrate, DSL, or conventional web architecture.

The map should identify:

- likely durable concepts;
- questionable assumptions;
- competing architectural directions;
- highest-risk unknowns;
- cheap experiments capable of distinguishing between them.

## Upstream Understanding

This request derives from `UND-20260903-XCTYG-3`, which interprets the retained greenfield intake as an exploratory research frame for AI-first architecture.

## Intended Audience

Primary: AI developers and AI coding agents evaluating what architecture would minimize required context while preserving correctness, auditability, and handover.

Secondary: human reviewers who need to inspect, challenge, and govern the resulting architecture choices.

## Observable Desired Outcomes

### evidence-map

Produce a concise map of Ariadne-derived, SimplyStore-derived, and independent candidate properties, with confidence and counterpressure visible.

### competing-directions

Describe at least two plausible architectural directions and one serious alternative that does not rely on a new DSL.

### falsification-targets

Identify assumptions whose failure would materially weaken the core small-semantic-system hypothesis.

### experiment-candidate

Recommend one small vertical slice suitable for comparing representations before selecting an architecture.

## Assumptions / Ambiguity

| Claim | Provenance | Evidence / question |
|---|---|---|
| Smaller semantic models may improve AI development | explicit hypothesis | Must be tested, not assumed |
| Ariadne contains durable concepts | explicit hypothesis | Needs historical/concrete examples and counterexamples |
| SimplyStore may provide useful primitives | explicit hypothesis | Needs separation of foundational semantics from human-facing convenience |
| DSLs may help | explicit hypothesis | Must show where complexity moves and whether auditability improves |
| Ordinary code might be simpler | explicit counter-hypothesis | Must remain a valid competing direction |

## Non-Goals

- Do not design a programming language.
- Do not rewrite Ariadne.
- Do not select SimplyStore as the foundation.
- Do not optimize for LOC.
- Do not create a DSL merely because examples are shorter.
- Do not implement product behavior in this request.

## Important Uncertainty / Assumption

The highest-leverage uncertainty is whether a compact semantic representation actually lowers the amount of project-specific context an unfamiliar AI must inspect to safely change behavior.

Cheap evidence should compare representations for the same small vertical slice and ask what an unfamiliar AI and a human reviewer must inspect to explain requirement-to-behavior causality.

## Risks

- A DSL may hide complexity in interpreter semantics.
- Ariadne's durable-looking ideas may be tied to historical CMS/PHP constraints.
- SimplyStore's JavaScript query model may undermine semantic compactness.
- Generated code may become trusted without an adequate derivation/verification story.
- AI-first architecture may become human-opaque if auditability is not tested early.

## Acceptance Shape

This request is satisfied when the project has a reviewed evidence map that:

- separates evidence from interpretation;
- includes counterexamples and rejected/competing alternatives;
- names the riskiest unknowns;
- proposes a first semantic experiment with evaluation criteria;
- does not harden a product architecture before evidence supports it.
