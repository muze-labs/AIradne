# Cycle: Graph-First Publication Experiment Design

## Analyze

Project state / prior evaluation that makes this cycle relevant:

Airadne has completed greenfield intake and accepted the initial architecture evidence map. The accepted evidence says the next useful move is to design a small publication-workspace semantic experiment before implementing product behavior or choosing a substrate.

Important risk / uncertainty / desired movement:

The highest-leverage uncertainty is whether stable IDs plus typed graph relationships and hierarchy-as-projection can reduce AI/human reasoning burden without moving complexity into hidden interpreter, query, authorization, or projection rules.

Relevant human direction / feedback:

The human confirmed this next cycle on 2026-09-03: design the graph-first publication experiment and comparison protocol.

The previous cycle's accepted feedback materially constrains this cycle: hierarchical identity is insufficient; Ariadne repeatedly hit the wall of forcing graph-based data into strict hierarchy; SimplyStore appears closer to the better model.

Governing higher-level plan / direction:

No durable roadmap exists yet. The accepted evidence map `EVD-20260903-XCTYG-8` is the governing input for this cycle.

Current position in that plan:

First design cycle after initial evidence acceptance. No implementation has begun.

## Plan

### Cycle Goal

Design the smallest fair publication-workspace experiment that can compare conventional explicit code, a graph-first object-space semantic kernel, and a SimplyStore-style commanded dataspace against the same behavior and evaluation criteria.

### Commitment Boundary

Human confirmation in conversation on 2026-09-03 after the proposed cycle goal was presented. Accepted inputs: `EVD-20260903-XCTYG-8` and `FBK-20260903-XCTYG-9`.

### Why Now / Why This Cycle Boundary

The next implementation cycle needs a fair test target. Designing the experiment first prevents accidental architecture selection by implementation convenience and keeps the core Airadne hypothesis falsifiable.

This cycle is narrower than building any representation. It is broader than choosing fixtures only because the comparison protocol, required behaviors, and falsification criteria must line up before implementation starts.

### Plan Continuity Decision

Continue from accepted evidence. The cycle deliberately applies the graph-first correction from the previous evaluation rather than reopening hierarchy as a neutral primitive.

### Current Starting Evidence

- `.spiral/project-context.md` records the project as a greenfield investigation into AI-first architecture.
- `EVD-20260903-XCTYG-8` recommends a publication-workspace experiment and records the representation comparison.
- `FBK-20260903-XCTYG-9` records the accepted correction that hierarchy should be projection/containment, not identity.
- `simplystore/` is available as evidence for commanded dataspace, immutable read views, semantic commands, and graph/link-shaped data.
- `ariadne/` is available as evidence for object-space semantics, projections, behavior selection, authorization, and historical hierarchy limits.

### Evaluation Basis

The cycle is successful when it produces a reviewed design artifact that:

- names the exact domain slice and fixtures;
- defines stable identity, typed relations, and hierarchy-as-projection for the slice;
- defines required behaviors shared by all compared representations;
- defines the three representation candidates and their boundaries;
- defines evaluation tasks and measurements for AI inspection, human auditability, and verification;
- names falsification conditions for each representation;
- explicitly defers implementation, language design, and substrate commitment.

### Likely Work

- Convert the accepted evidence-map experiment sketch into a concrete protocol.
- Define minimal graph fixtures and behaviors for publication workspace.
- Define comparison rules for conventional code, graph-first object-space kernel, and commanded dataspace.
- Define what evidence each implementation must produce later.
- Record the result as `DES-20260903-XCTYG-11`.

### Explicit Non-Goals

- Do not implement the experiment.
- Do not design a DSL grammar.
- Do not choose SimplyStore as the substrate.
- Do not choose a frontend/backend framework.
- Do not optimize for line count.
- Do not create generated runtime code.

### Pause / Re-Plan Conditions

- The experiment cannot be made small enough to implement in the next cycle.
- The fixtures accidentally require a full CMS or real persistence system.
- The comparison would privilege one representation through mismatched behavior.
- Human review finds the slice does not exercise the hierarchy-as-projection risk.

## Evaluate

Integrated result against cycle goal:

The cycle produced a design artifact for a fair publication-workspace experiment. It defines the shared domain slice, graph identity model, typed relations, hierarchy-as-projection constraint, required query/mutation/validation/authorization/contextual behavior, compared representations, evaluation tasks, metrics, and falsification conditions.

Evidence / acceptance result:

Design artifact created: `.spiral/designs/DES-20260903-XCTYG-11-graph-first-publication-experiment.md`.

Project-local Turtle parse passed before the design commit.

Human acceptance is pending.

Metric or risk movement:

- Reduced risk of accidental architecture selection by making conventional code, graph-first object-space, and commanded dataspace implement the same fixture and behavior surface.
- Preserved the hierarchy correction by making `contains` a projection relation and requiring non-hierarchical references, topics, variants, language, workspace, and authorization paths.
- Made falsification conditions explicit for each representation and for the broader Airadne hypothesis.

What changed in our understanding:

The experiment must test explanation quality as a first-class behavior, not just runtime correctness. Authorization denial, behavior precedence, and projection traversal need inspectable explanation paths or the semantic approach does not serve AI/human auditability.

Surprises / model mismatches:

Designing the fixture made behavior precedence unavoidable. The cycle fixed one deterministic precedence order for comparison fairness while explicitly not promoting it to final Airadne semantics.

Known compromises:

The design is still a protocol, not evidence from implementation. It may prove too large for a single implementation cycle and may need to be split by representation or by shared fixture/test harness.

Unresolved issues within current goal:

Human review may find that the fixture is too small, too large, or missing a historically important Ariadne graph pain point.

Candidate next-cycle inputs:

- Implement the shared fixture and conventional explicit-code baseline first, to establish the control condition.
- Implement a minimal graph-first object-space kernel against the same fixture and tests.
- Implement a commanded dataspace version against the same fixture and tests.
- Alternatively, split the next cycle into shared fixture/test harness only if the comparison surface is still too broad.
