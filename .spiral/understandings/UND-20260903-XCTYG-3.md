# Understanding: AI-First Architecture Exploration Frame

## Current Interpretation

Airadne is a greenfield research project exploring whether AI-first software architecture should be organized around a small explicit semantic core plus compact domain-specific representations.

The core hypothesis is not accepted as truth. The project should investigate whether a smaller executable semantic model genuinely improves AI reasoning, modification, verification, and handover, and should actively look for evidence that falsifies or narrows that claim.

The immediate project direction is evidence gathering rather than implementation or language design. Ariadne and SimplyStore are relevant sources of evidence, but neither is an oracle or predetermined foundation.

The first useful output should be a map of likely durable concepts, questionable assumptions, competing architectural directions, highest-risk unknowns, and cheap experiments capable of distinguishing between them.

## Current Effective Behavior / Evidenced Gap

This repository currently has no product implementation. It contains the Spiral methodology and reference submodules for Ariadne and SimplyStore.

The evidenced gap is therefore not an unmet product feature. The gap is that the project needs a durable, inspectable research frame and then a first evidence-producing cycle before design or implementation can be justified.

Initial evidence gathered so far:

- Ariadne exposes a filesystem-like content repository and request model where HTTP paths resolve into object paths plus behavior/template names.
- Ariadne has long-lived mechanisms for local/contextual behavior selection, including object/type/template/language lookup and object-local templates exposed as files through the FTP interface.
- Ariadne implements hierarchical grants through path ancestry, user/group grants, and modifiers.
- SimplyStore exposes a small in-memory dataspace, immutable query side, meaningful command log, recovery status, and derived indexes.
- SimplyStore's JavaScript query surface is convenient, but may expand the semantic burden for AI reasoning because arbitrary JavaScript becomes part of the behavior model.

These observations support investigation. They do not yet prove which architecture should be built.

## Provenance Confidence

Evidenced. The project frame is explicit in the retained human source; the concrete examples are supported by read-only inspection of the Ariadne and SimplyStore submodules.

## Remaining Uncertainty

- Whether semantic compression actually reduces the context required for correct AI changes.
- Whether DSLs would improve or harm human auditability.
- Which Ariadne concepts remained useful because they are fundamental, and which were artifacts of PHP/CMS-era constraints.
- Whether SimplyStore's command/recovery model is a useful substrate for Airadne.
- Whether arbitrary JavaScript queries should be constrained, replaced, generated, or left conventional.
- How to measure AI handover cost in a cheap but meaningful first experiment.

## Commitment / Disposition

Accepted as the current project interpretation before opening the first cycle.

This understanding authorizes planning an evidence-gathering cycle. It does not authorize implementation of a DSL, Ariadne rewrite, SimplyStore-based architecture, or product system.

## Consequence

Create a request for the first evidence map, then open a first Spiral cycle to produce that map and propose the cheapest discriminating semantic experiment.
